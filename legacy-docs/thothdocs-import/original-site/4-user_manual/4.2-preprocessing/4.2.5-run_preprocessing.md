# Running the Preprocessing

## 1 - Introduction
Preprocessing is a fundamental step in ThothAI to prepare database data for advanced analysis and operations. This section explains what happens when you run preprocessing, which artifacts are created/saved, how the backend stores them, and how the ThothAI UI guides the process.

## 2 - What happens during preprocessing
When you start the "Run Preprocessing" action, ThothAI performs a sequence of tasks to prepare the database for efficient processing. This includes:

- **Creating LSH (Locality-Sensitive Hashing) signatures**: compact representations that support fast similarity searches across database elements.
- **Generating context vectors**: semantic representations of database columns that improve understanding and querying.

The process runs in the background so the UI remains responsive while preprocessing is underway.

## 3 - Information created and saved
Two main types of data are produced:

- **LSH signatures**: stored on the filesystem, arranged in directory structures.
- **Context vectors**: stored in the vector database (e.g., Qdrant) linked to the relational database.

## 4 - Backend storage details
ThothAI’s backend (which supports ThothSL) saves preprocessing outputs as follows:

- **LSH signatures**: stored under `<lsh_root>/<db_mode>_databases/<database_name>` (e.g., `prod_databases/sales_dw`).
- **Context vectors**: saved in the configured vector DB (Qdrant, etc.), mirroring the associated relational database settings.

## 5 - User interface for preprocessing
The ThothAI UI provides an easy workflow to start and monitor preprocessing:

- **Preprocessing page**: The “Preprocess” view shows the current workspace, associated database, and preprocessing status. A “Run Preprocessing” button starts the process.
- **Background execution**: Runs in a separate thread; the UI polls status so the user sees whether it’s still running or finished.
- **State feedback**: On completion, the UI reports success or errors plus relevant log messages.

This integration ensures users can manage preprocessing without dealing with the underlying technical details.
