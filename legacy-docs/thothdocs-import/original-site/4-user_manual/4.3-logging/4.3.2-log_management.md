# 3.4.2 Log Management

## Logging system overview

ThothSL implements a dual logging system to maximize visibility and traceability. It supports both real-time monitoring and post-mortem analysis.

## Logging architecture

### Dual logging: Logfire + filesystem

ThothSL logs events simultaneously to:

1. **Logfire**: Cloud monitoring for real-time traces, performance metrics, advanced analysis
2. **Local filesystem**: Files for direct access, local persistence, offline analysis

This ensures logs are always accessible via Logfire’s UI and on-disk files.

## Filesystem log structure

### Log directory

Filesystem logs reside in:
```
/ThothSL/logs/
```

Structure:
- **Root**: `/logs/` at project root
- **Archive folder**: `/logs/archives/` for historical retention

### Docker setup and bind mount

Inside Docker, the log directory is configured with:

- **Docker volume**: `/logs/` inside the container is mapped to the host filesystem
- **Bind mount**: Authorized users can read log files directly on the host
- **Persistence**: Logs survive container restarts

Benefits for admins:
- Real-time access
- Offline analysis
- Custom backup policies

## Automatic log management

### Rotation and cleanup

ThothSL automatically manages on-disk logs through intelligent rotation:

#### Rotation logic

It works by:

1. **Periodic grouping** by:
   - Time interval (daily/weekly)
   - File size
   - Detail level

2. **Deletion criteria**:
   - **Old logs**: Removed after a configurable period (30 days default)
   - **Retention policy**: Keep a minimum number of historical files
   - **Archiving**: Important logs moved to `/logs/archives/`

#### Management steps

Steps:

1. **Continuous monitoring** of size/age
2. **Compression** of older logs
3. **Archiving** into the archives folder
4. **Cleanup** according to retention rules

### Logging configuration

#### Log levels

Supported levels:
- **DEBUG**: Detailed developer info
- **INFO**: Normal operations
- **WARNING**: Potential issues
- **ERROR**: Non-blocking errors
- **CRITICAL**: Severe failures needing immediate attention

#### Log format

Each entry follows:
```
[Timestamp] [Nome Logger] [Livello] - Messaggio
```

## Accessing logs

### Authorized users

Server-access users can:

1. **Read files directly**:
   ```bash
   tail -f /percorso/thothsl/logs/thoth_app.log
   ```

2. **Use Docker logs**:
   ```bash
   docker logs -f thoth-ai
   ```

3. **View in Logfire**: Web monitoring interface

### Monitoring integrations

Integrates with:
- **Logfire dashboard** (cloud monitoring)
- **ELK Stack** (advanced analysis)
- **Grafana** (custom dashboards)
- **Custom scripts** (automation)

## Log management best practices

### For administrators

1. Monitor file growth regularly
2. Back up critical logs strategically
3. Configure appropriate retention periods
4. Keep disk space in check

### For developers

1. Use the proper log level for each event
2. Provide descriptive, contextual messages
3. Maintain consistent formatting for easier analysis

## Troubleshooting

### Common issues

1. **Low disk space**: Automatic cleanup handles it
2. **Logs not visible**: Check directory permissions
3. **Logfire not receiving data**: Verify token config

### Useful commands

```bash
# Verificare spazio utilizzato
du -sh /percorso/thothsl/logs/

# Controllare log in tempo reale
tail -f /percorso/thothsl/logs/thoth_app.log

# Analizzare log per errori
grep -i error /percorso/thothsl/logs/thoth_app.log
```

ThothSL’s logging system offers a robust, flexible monitoring solution so both developers and admins can keep the application running smoothly.
